\section{Motivation: wide-isolation-window DIA}
In data-independent acquisition with \emph{wide} quadrupole isolation windows, a single
MS2 window co-isolates many precursors, so a confident identification needs evidence that the
signal is real and not bleed-through from a co-isolated neighbor or chromatographic
interference. The \textbf{flanking-window features} provide this by contrasting two regions of
the \emph{same} isolation window:
\begin{itemize}
  \item the \textbf{core}: the contiguous run of MS2 cycles, centered on the precursor's apex
        scan, where the precursor passes the search threshold (it is PSM-backed by
        construction --- one MS2 scan per cycle per window);
  \item the \textbf{flank}: scans of the same isolation window in the cycles immediately
        \emph{flanking} the core, where the precursor has \emph{no} passing PSM.
\end{itemize}
A genuine precursor concentrates MS1 and fragment signal in the core with co-eluting
fragments; interference smears into the flank or shows fragments that do not track the
precursor.

\section{Where they are computed (two pipeline stages)}
\begin{enumerate}
  \item \textbf{MainSearch} (\code{SearchMethods/MainSearch/scoring.jl}) --- after
        best-per-precursor selection, \code{\_mainsearch\_flanking\_core\_bounds!}
        (\code{:811}) finds the core window, and the per-precursor loop (\code{:1045--1097})
        writes the intermediate ``core'' columns into the fold Arrow files:
        \code{flanking\_core\_scan\_min}, \code{flanking\_core\_scan\_max},
        \code{n\_contiguous\_scans}, \code{flanking\_core\_ms1\_m0\_signal},
        \code{flanking\_core\_frag\_signal}, plus the smoothed apex columns
        \code{frag1..8\_smoothed\_intensity}.
  \item \textbf{PrecursorScoringSearch} (\code{PrecursorScoringSearch.jl:199} $\to$
        \code{add\_wide\_window\_features\_to\_fold\_file!} in \code{wide\_window\_features.jl})
        --- reads the core columns, gathers the flank scans, extracts MS1 + fragment
        intensities from the raw spectra, computes the 11 flank feature values in
        \code{\_wide\_flank\_feature\_values} (\code{:58}), and writes them back. The two
        \code{*\_signal} core columns are intermediate and dropped afterward (\code{:893}).
\end{enumerate}
The final list \code{FLANKING\_WINDOW\_FEATURES} (\code{model\_config.jl:49}) feeds the
second-pass ScoringSearch LightGBM.

\section{Defining the core, and what is raw vs smoothed (MainSearch)}
\code{\_mainsearch\_flanking\_core\_bounds!} sorts a precursor's scored rows by
\code{(cycle, scan)}, finds the apex (selected) scan, and walks outward while each neighbor
both passes and is in the immediately adjacent cycle ($\pm 1$):
\begin{lstlisting}
while lo>1 && pass_mask[prev] && cycle[prev]==cycle[cur]-1; lo-=1; end   # left
while hi<len && pass_mask[next] && cycle[next]==cycle[cur]+1; hi+=1; end # right
\end{lstlisting}
It returns the core scan range \code{scan\_min}/\code{scan\_max}, \code{n\_contiguous\_scans},
and the apex/left/right boundary rows.

\paragraph{Core \emph{signals} are summed from RAW intensities.} Over the core scans
(\code{scoring.jl:1082--1093}):
\[
\text{core\_ms1\_m0\_signal} = \!\!\sum_{\text{core scans}}\!\! \text{ms1\_m0}, \qquad
\text{core\_frag\_signal} = \!\!\sum_{\text{core scans}}\ \sum_{r=1}^{8} \text{frag}_r^{\text{raw}} .
\]
Here $\text{frag}_r^{\text{raw}}$ are the matched per-scan intensities
(\code{MAINSEARCH\_FRAGMENT\_INTENSITY\_COLUMNS}); \textbf{no smoothing is applied to the sum.}

\paragraph{The smoothed values are a separate, per-fragment APEX height.}
\code{\_mainsearch\_radius1\_smooth\_fragments!} (\code{:917}) computes, for each of the 8
fragments, a radius-1 weighted average over the apex scan and its two adjacent core scans:
\[
\text{frag}_r^{\text{smoothed}} \;=\; \frac{2\,a_r + l_r + r_r}{\text{denom}},
\]
where $a_r,l_r,r_r$ are the raw apex/left/right intensities and \code{denom} counts the
present neighbors. This is \emph{not} summed --- it is a denoised \emph{peak height}. A
single-scan raw apex is spiky; the 3-point weighted average is a stabler estimate of the true
peak. These \code{frag*\_smoothed\_intensity} values are used (i) directly as LightGBM
features and (ii) as the core apex in the flanking \code{frag\_apex\_gt2x} feature below.
\emph{So smoothing benefits the apex/peak-height comparison, not the sum.}

\section{Gathering the flank and extracting signal (PrecursorScoringSearch)}
\begin{itemize}
  \item \code{\_wide\_window\_index\_spectra} (\code{:286}) indexes every MS2 scan by its
        isolation window key \code{(center\_mz, isolation\_width)} --- one scan per cycle.
  \item \code{\_wide\_group\_flank\_window\_scans\_from\_core!} (\code{:420}) collects the
        same-window scans in cycles flanking the core (outside
        $[\text{scan\_min},\text{scan\_max}]$, within \code{WIDE\_WINDOW\_CYCLE\_MARGIN}$=3$
        cycles). No flank scans $\Rightarrow$ zero/default feature values.
  \item \code{\_wide\_top\_fragment\_idxs} / \code{\_wide\_group\_fragment\_windows} pick the
        top-8 library fragments and m/z windows; scan-centric extraction
        (\code{\_wide\_fill\_scan\_centric\_\{ms1\_m0,fragments\}!}, batched at $50000$ groups)
        fills the \emph{raw} flank vectors \code{flank\_ms1\_m0} and \code{flank\_fragments}
        ($\#\text{flank scans}\times 8$).
\end{itemize}

\section{The features (\code{\_wide\_flank\_feature\_values}, line 58)}
Let $c_{m0},c_f$ be the core MS1-m0 / fragment signals (raw sums); $a_r$ the smoothed core
apex of fragment $r$; $\mathbf{m}$ the raw flank MS1-m0 vector (one per flank scan); $F$ the
raw flank fragment matrix (scan $\times$ fragment). Floor all intensities at $0$; let
$s_j=\sum_r F_{j,r}$, and $\rho(\cdot,\cdot)$ be Pearson correlation
(\code{\_wide\_window\_pcor}; $0$ for $<2$ points or zero variance).

\feat{flanking\_ms1\_m0\_candidate\_fraction}{Float32}
$\dfrac{c_{m0}}{c_{m0}+\sum_j \mathbf{m}_j}$ --- fraction of the precursor's MS1 monoisotopic
(m0) signal sitting in the core vs.\ spread into flank scans. $\to 1$ for a clean precursor.

\feat{flanking\_frag\_candidate\_fraction}{Float32}
$\dfrac{c_f}{c_f+\sum_j s_j}$ --- the same core-vs-flank fraction for summed fragment signal.

\feat{flanking\_ms1\_frag\_sum\_corr}{Float32}
$\rho(\mathbf{m},\mathbf{s})$ across flank scans --- do the MS1 precursor and the fragment sum
co-vary off-apex? (co-elution sanity check in the flank).

\feat{flanking\_frag\_corr\_mean}{Float32}
mean of all pairwise $\rho(F_{:,a},F_{:,b})$ over flank scans, among fragments with signal ---
average fragment-fragment co-elution in the flank.

\feat{flanking\_n\_correlated\_fragments}{UInt8}
count of fragments whose leave-one-out correlation
$\rho\!\big(F_{:,r},\,\mathbf{s}-F_{:,r}\big) > 0.7$ (\code{WIDE\_WINDOW\_CORR\_THRESHOLD}) ---
how many fragments track the rest.

\feat{flanking\_n\_correlated\_fragments\_bitvec\_rank}{UInt16}
\code{\_bitvec\_pattern\_rank} of the 8-bit mask of \emph{which} fragments exceeded $0.7$ ---
a learned categorical encoding of the correlated-fragment \emph{pattern}, not just the count.

\feat{flanking\_frag\_corr\_strength}{Float32}
$\sum_r \max(\min(\rho_r,1),0)$ over the leave-one-out correlations $\rho_r$ --- continuous
total correlation strength across the 8 fragments.

\feat{flanking\_frag\_corr\_effective\_n}{Float32}
$\dfrac{\big(\sum_r \rho_r^{+}\big)^2}{\sum_r (\rho_r^{+})^2}$ (participation ratio of the
positive leave-one-out correlations) --- the effective number of co-eluting fragments.

\feat{flanking\_frag\_corr\_best\_m0}{Float32}
$\rho(F_{:,b^\*},\mathbf{m})$ where $b^\*$ is the fragment with the highest mean pairwise
correlation (the ``anchor'') --- does the best fragment track the MS1 precursor across the flank?

\feat{flanking\_signal\_support}{Float32}
$\dfrac{\#\{j:\mathbf{m}_j>0 \text{ or } s_j>0\}}{\#\text{flank scans}}$ --- fraction of flank
scans carrying any signal.

\feat{frag\_apex\_gt2x\_flank\_bitvec\_rank}{UInt16}
\code{\_bitvec\_pattern\_rank} of the 8-bit mask of fragments whose smoothed \emph{core apex}
$a_r \ge 2\times$ their flank average $\bar F_{:,r}$ --- which fragments genuinely peak at the
apex rather than being flat/interference. (This is the one feature that uses the smoothed apex.)

\feat{n\_contiguous\_scans}{UInt16}
(from the core bounds, not \code{\_wide\_flank\_feature\_values}) the number of contiguous
cycles in the core run --- how many cycles the precursor persisted.

\medskip
\noindent The 11 values from \code{\_wide\_flank\_feature\_values} plus
\code{n\_contiguous\_scans} make up the 12-entry \code{FLANKING\_WINDOW\_FEATURES}.

\section{Helper functions}
\feat{\_mainsearch\_flanking\_core\_bounds! (scoring.jl:811)}{MainSearch}
Find the contiguous-cycle core window around the apex; return scan\_min/max, n\_scans, and the
apex/left/right boundary rows.

\feat{\_mainsearch\_radius1\_smooth\_fragments! (scoring.jl:917)}{MainSearch}
Radius-1 weighted apex smoothing $(2a+l+r)/\text{denom}$ producing
\code{frag*\_smoothed\_intensity}.

\feat{\_wide\_window\_pcor (:5)}{wide\_window\_features.jl}
Single-pass Float32 Pearson correlation; $0$ if $<2$ points or zero variance.

\feat{\_wide\_candidate\_signal\_fraction (:32)}{wide\_window\_features.jl}
$\text{core}/(\text{core}+\text{flank})$, guarding divide-by-zero.

\feat{\_wide\_flank\_feature\_values (:58)}{wide\_window\_features.jl}
Compute the 11 flank features from the core scalars/apex and the raw flank arrays.

\feat{\_wide\_window\_index\_spectra (:286)}{wide\_window\_features.jl}
Index scans by isolation window \code{(center\_mz, isolation\_width)}.

\feat{\_wide\_group\_flank\_window\_scans\_from\_core! (:420)}{wide\_window\_features.jl}
Collect same-window scans in cycles flanking the core (margin $=3$ cycles).

\feat{\_wide\_fill\_scan\_centric\_\{ms1\_m0,fragments\}! (:578/:601)}{wide\_window\_features.jl}
Read raw-spectra MS1 m0 and fragment intensities at each flank scan (scan-centric, batched).

\feat{\_bitvec\_pattern\_rank}{shared}
Map an 8-bit fragment pattern mask to a learned rank (file-specific table).

\section{Constants}
\code{WIDE\_WINDOW\_CYCLE\_MARGIN}$=3$ (flank reaches up to 3 cycles either side);
\code{WIDE\_WINDOW\_CORR\_THRESHOLD}$=0.7$ (correlated-fragment cutoff);
\code{FLANKING\_SCAN\_CENTRIC\_BATCH\_SIZE}$=50000$ (groups per scan-extraction batch).

features belong only to the second one.

\section{Consumption}
The features are appended to the per-fold second-pass PSM Arrow files and feed the ScoringSearch
second-pass LightGBM (\code{FLANKING\_WINDOW\_FEATURES}). They are most informative on
wide-window instruments (e.g.\ Sciex SWATH), where co-isolation is heaviest, and near-constant
on narrow-window data.
